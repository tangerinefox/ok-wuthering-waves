## 二、提取流程（encore.moe）

浏览器工具在页面里执行 JS，把正文取出来。

**核心思路：在真实 DOM 上把图片替换成文字，取完再还原。**

```
1. 遍历页面所有 <img>，取其 alt 属性
2. 按键图标做中文映射（LeftMouseButton → 鼠标左键）
3. 用 <span> 把 img 换掉，文字写成 [xxx]
4. 取 document.body.innerText
5. 把 img 换回去（恢复页面）
6. 保存到文件
7. 本地用 JSON.parse 还原换行，再做筛选和清理
```

## 二·续、提取流程（Prydwen 角色页）

**一句话：Prydwen 的角色页是"折叠的集合"，不点全就等于没抓。**

2026-10-07 抓心的时候第一次只抓了默认状态，漏掉一大半；后来重抓才发现差距。

### 页面结构

**主标签 5 个**，默认只展开第一个：

```
Kit                 技能全文 + 倍率表 + 共鸣链
Review              机制解析（最值钱的都在这里，全是结论性的东西）
Build               武器 / 声骸 / 副词条 / 材料
Gameplay and teams  循环轴、操作细节、配队评价
Calculations        伤害模拟（按共鸣模态分开给数值）
```

**每个主标签下还挂子标签**，同样要逐个点：

```
Active skills / Passive skills / Concerto skills   技能分类
Unison / Electro Flare                             两个共鸣模态
```

**第三层折叠**：页面上所有 `.pw-accordion-button`，包括——

- 每个技能的 **Multipliers（倍率表）**
- Build 里**每一把武器**、**每一个声骸**的详情

### 抓取步骤

```
1. 点开一个主标签
2. 点开它下面的每个子标签
3. 把页面上 aria-expanded="false" 的折叠按钮全部点开
4. 取 .generic-page 的 innerText
5. 回到 1，换下一个主标签
```

### 点全 vs 不点全

| | 字符数 | 漏掉了什么 |
|---|---|---|
| 只抓默认状态 | 4 万多 | 机制解析、倍率表、武器声骸、伤害模拟 |
| **全部点开** | **66,682** | — |

### 去重

每个标签抓下来的都是**整页文本**，相邻两段高度重叠。存盘前做一次**前后缀差分**，只保留"相较上一段新增的部分"，否则文件里全是重复。

### 一条甄别

Prydwen 是**攻略站，不是数据库**，它的数值描述偶尔和官方文本对不上。

心那次就有一条：Prydwen 说 1 链里有个 **210%** 的分支（"命中并消耗 5 层霆心域"），**官方中文文本里没有这句**。

**对不上的地方以 encore.moe 的官方文本为准**，Prydwen 的留着当线索。

## 三、踩过的坑（重要）

### 坑 1：`innerText` 在"克隆出来"的节点上会失效

**现象**：想省事，先把 `document.body` 克隆一份、在克隆体上替换图片再取文本。结果换行全丢，整篇挤成一坨。

**原因**：`innerText` 依赖元素在渲染树里才生效。脱离文档的克隆节点没有渲染信息，退化成 `textContent` 的效果，块级元素之间的换行就没有了。

**解法**：**在真实 DOM 上替换，取完立刻还原。** 页面会闪一下，无所谓。

### 坑 2：工具存出来的文本是 JSON 字符串

**现象**：文件打开是一整行，换行全是 `\n` 字面量，外面还裹着引号。

**原因**：保存结果时把字符串做了 JSON 序列化。

**解法**：读进来先 `JSON.parse()` 还原。

### 坑 3：图片上的字全丢了

**现象**：操作说明那节写的是"应答形态：应答之心满时，按住 ___"——后面空白。

**原因**：按键是 `<img>`，`innerText` 取不到图片内容。

**解法**：取 `<img>` 的 `alt` 属性。这批图标的 alt 写得很规范（`LeftMouseButton`、`E`、`R`），所以能还原成 `[鼠标左键]` `[E]` `[R]`。

**注意**：**没有 alt 的图片会变成空**，需要给个兜底文字（比如 `[图片]`），否则信息静默丢失。

### 坑 4：中文参数是 `lang=zh-Hans`

**现象**：试了 `?lang=zh`、`?lang=cn`、`?lang=zh-cn`，页面内容**全是英文**，没有任何报错，看不出哪里不对。

**解法**：正确参数是 **`?lang=zh-Hans`**（网站界面上的语言切换器切过去，地址栏就是这个）。

**教训**：猜参数不如直接看网站切语言后的 URL。

### 坑 5：网站只翻译正文，不翻译区块标题

**现象**：切中文后，故事、技能描述都成中文了，但 `Forte Examination Report`、`Stories`、`Voicelines`、`Birthday:`、`Tags`、`MATERIALS`、`SKILL LEVEL` 这些**还是英文**。

**解法**：扫出全文的**纯英文行**（这次是 80 个），做一张替换表逐行替换。只对"整行完全匹配"的行替换，避免误伤正文里的英文。

### 坑 6：页面上的机制示意图是空占位符

**现象**："基础机制"那节下面挂着三张图，看着像机制说明图。

**真相**：`src` 指向 `/images/placeholder.png`——**站点作者没上传真图**，就是个占位符。别指望从那儿看机制。

### 坑 7：媒体资源是懒加载的，纯文本抓不到

**现象**：技能演示视频、3D 模型、抽卡动画，页面上有入口但 DOM 里没有。

**解法**：翻浏览器的**网络请求记录**，里面能看到技能图标、属性图标、立绘、抽卡 Spine 图的完整 URL；至于视频和 3D 模型，因为没滚动到就根本没请求，只能记录"页面上哪个位置有入口"。

### 坑 8：接口比页面好用（术语表那次）

**现象**：站点术语表有 **28 页**，每页 20 条，逐页翻太慢。

**解法**：翻网络请求找到接口 `https://api-v2.encore.moe/api/en/term`，**一次拿全 655 条**。详情接口是 `api/en/term/{id}`。

**但要注意**：这个接口**只有英文描述**，中文参数不存在（`zh`、`cn` 都返回 400）。术语的中文名在 `TermName` 字段里，中文描述没有。

### 坑 9：Claude 自带的网页抓取抓不了 GitHub

**现象**：用内置的 WebFetch 抓 `github.com`，返回"无法验证域名安全"。

**解法**：改用**本机的 `curl`**（走本地代理），能正常访问。同样地，`wutheringwaves.fandom.com` 直接超时，抓不到。

**所以**：遇到抓不下来的站，先试 curl，不要死磕内置抓取。

## 三·续、工具层的坑：为什么重抓花了那么久

这几个不是网站的问题，是**工具本身**的问题。2026-10-07 那次重抓，大半时间耗在这儿。

### 坑 10：`browser_evaluate` 的 `filename` 参数是假的

**现象**：调用时带上 `filename`，返回"Evaluation result"并给一个文件链接，看着像存好了。

**真相**：**它根本不写文件。**

**代价**：我信了它，中间一次操作把一个已有文件覆盖成了 184 字节的垃圾。

**教训**：**任何"已保存"的回执，都要 `ls` 一下确认。** 不要凭返回值相信文件存在。

### 坑 11：新开一个 Chrome 抓 Prydwen 会被 Cloudflare 挡

**现象**：用 Playwright 起一个全新的 Chrome 打开 Prydwen，标题是 `Just a moment...`，正文只有 262 字符，写着 "Performing security verification"。

**解法**：**只能用已经通过验证的那个浏览器会话**（平时在用的那个）。新开的干净配置过不去。

### 坑 12：页面的 CSP 挡住 `fetch` 到本地

**现象**：想"在页面里抓完 → POST 到本地一个小服务 → 由本地落盘"，`fetch` 直接 `Failed to fetch`。

**原因**：Prydwen 有 Content-Security-Policy，限制了 `connect-src`。

**推论**：`navigator.sendBeacon` 同样会被挡（同一套规则）。

### 坑 13：`browser_run_code_unsafe` 里没有 Node 环境

**现象**：想在 Playwright 进程里直接写文件。探了一遍：

- `typeof require` → `undefined`
- `typeof process` → `undefined`
- `await import('node:fs/promises')` → `ERR_VM_DYNAMIC_IMPORT_CALLBACK_MISSING`

**结论**：那是个干净的 VM，**碰不到文件系统**。

### 最后走通的路子：借浏览器下载

```js
// 1) 在页面里把文本做成 Blob，点一个 <a download>
page.evaluate(t => {
  const url = URL.createObjectURL(new Blob([t], { type: 'text/plain;charset=utf-8' }));
  const a = document.createElement('a');
  a.href = url; a.download = 'x.txt';
  document.body.appendChild(a); a.click(); a.remove();
}, text);

// 2) 在 Playwright 进程里接住这次下载，直接存到目标路径
const [dl] = await Promise.all([
  page.waitForEvent('download'),
  /* 上面那个 evaluate */
]);
await dl.saveAs('C:/.../目标文件.txt');
```

**为什么这条路通**：

- `download.saveAs()` 是 **Playwright 自己写文件**，不需要 `fs` → 绕开坑 13
- 下载属于**导航类操作**，不受 CSP 的 `connect-src` 限制 → 绕开坑 12

（另：`node_repl` 里可以 `import('playwright')`，但要先用 `js_add_node_module_dir` 把 playwright 所在的 `node_modules` 加进搜索路径——本机在 npm 的 `_npx` 缓存里。不过它起的浏览器同样过不了 Cloudflare，所以对 Prydwen 没用。）

## 四、两份产出怎么切的

从同一份全量文本里切出两份：

- **全量版**：去掉顶部导航、赞助广告、页脚；图片转文字；末尾附资源链接清单。
- **技能属性版**：从"启用 Live2D"之后开始（跳过导航），**截到"共鸣回路检验报告"之前**——再往后就是背景故事、语音、珍视之物这些剧情内容。

**切分锚点**（英文版和中文版都用这两个词定位）：
- 起点：`Enable Live2D` / `启用 Live2D`
- 截断点：`Forte Examination Report` / `共鸣回路检验报告`

## 六、抓新角色时的清单

### A. encore.moe —— 技能文本

1. 拿角色 ID，打开 `https://encore.moe/character/{ID}?lang=zh-Hans`
2. 在真实 DOM 上替换 `<img>` → `[alt]`，取 `innerText`，还原
3. 存文件，`JSON.parse` 还原换行
4. 扫纯英文行，用替换表换成中文
5. 切两份：全量版（截到"启用 Live2D"之后）、技能属性版（再截到"共鸣回路检验报告"之前）
6. 翻网络请求，把图片/媒体 URL 整理进附录

### B. encore.moe —— 查机制名词

7. 打开 `https://encore.moe/term?lang=zh-Hans`，用页面上的搜索框
   （搜索词会进地址栏，形如 `&search=电磁`，也可以直接拼 URL）

### C. Prydwen —— 攻略 / 循环 / 数值

8. **5 个主标签逐个点开**：Kit / Review / Build / Gameplay and teams / Calculations
9. **每个主标签下的子标签也逐个点开**：
   Active skills / Passive skills / Concerto skills / Unison / Electro Flare
10. **展开所有折叠**：`aria-expanded="false"` 的按钮全部点开
    （Multipliers 倍率表、Build 里的每把武器、每个声骸）
11. 取 `.generic-page` 的 innerText，**相邻段做前后缀差分去重**
12. 落盘走**浏览器下载 + `download.saveAs()`**（见坑 10~13；**别用 `filename` 参数**）
13. **存完 `ls` 一下确认**，不要信工具的回执

**"抓全了没有"的自检**：Prydwen 全量抓下来应该是 **6 万多字符**。
如果只有 4 万多，说明标签没点全。
